# Бот оценок учебной группы

Python 3.11+, Linux/macOS, aiogram 3, SQLite. Один бот — одна группа и один администратор.
Бот читает общедоступные Google Sheets, показывает оценки и присылает личные уведомления.

## Быстрый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
cp .env.example .env
# Заполните BOT_TOKEN и CONTACT_USERNAME
gradebot admin 123456789
gradebot run
```

`BOT_TOKEN` выдаёт @BotFather. `CONTACT_USERNAME` — контакт администратора для сообщений об отказе
в доступе. `DATABASE_PATH` по умолчанию `grades.sqlite3`; `POLL_INTERVAL` — интервал в секундах,
по умолчанию 60, минимум 10. Переменные окружения имеют приоритет над `.env` в каталоге запуска;
`--interval` переопределяет `POLL_INTERVAL`. После изменения настроек перезапустите бота.

Администратор назначается только локально командой `gradebot admin TELEGRAM_ID`.
Для другой БД: `gradebot --db /path/group.sqlite3 admin TELEGRAM_ID`.
Повторный вызов меняет администратора. Новый администратор открывает `/start` и сразу получает
панель управления; ФИО для управления не требуется. Чтобы получать свои оценки, он добавляет себя
в список пользователей тем же способом, что студентов.

## Пользователи

В «Добавить пользователей» (`/access`) отправляйте карточки контактов и вводите ФИО как в ведомости
Можно отправить несколько контактов подряд — бот запросит ФИО для каждого по очереди
Кнопка «Выбрать пользователя» работает и для людей без юзернейма
После последнего ФИО нажмите «Сохранить всех» — весь список сохранится одной транзакцией
Повторный контакт обновляет ФИО той же строки, а не создаёт дубликат
Максимум 50 пользователей за одно добавление

У контакта должен быть Telegram ID — карточки только с телефоном не принимаются
Для таких контактов используйте кнопку выбора пользователя
Телефон не сохраняется и не используется для поиска
Импорт по юзернеймам удалён, дополнительные Telegram API-ключи и Telethon не нужны

До «Сохранить всех» пользователи не получают доступ
«Отмена» и `/cancel` удаляют весь черновик; перезапуск тоже сбрасывает незавершённый список
Сохранение добавляет/обновляет выбранных людей, остальные пользователи сохраняются

«Пользователи» (`/members`) показывает ФИО, ID и статус первого входа
Для исправления ФИО добавьте тот же контакт с новым именем
При смене ФИО очищаются снимки сравнения и ожидающие уведомления об оценках
Студент не может менять ФИО самостоятельно

«Закрыть доступ» (`/revoke`) показывает список с кнопками и запрашивает подтверждение
Удаляются разрешение, регистрация, снимки, личные страницы и очередь сообщений пользователя
Уже отправленные сообщения в Telegram остаются
Доступ текущему администратору так закрыть нельзя

Доступ определяется только сохранённым Telegram ID
Смена или передача юзернейма не влияет на права
Студент нажимает «Старт» и получает меню без ввода имени
Посторонним бот отказывает в доступе и показывает контакт администратора, если он задан
В групповых чатах оценки не показываются

## Меню студента

- **«Мои оценки»** (`/grades`) — оценки из сохранённого кэша, без ожидания Google.
- **«Таблицы»** (`/tables`) — предметы, ссылки, время обновления.
- **«Уведомления»** (`/notifications`) — выключить или включить уведомления об изменениях оценок.
- **«Помощь»** (`/help`) — справка и контакт администратора.
- **«Предложить таблицу»** (`/suggest`) — название, затем ссылка; предложение проверяет администратор.
- `/cancel` — отменить текущий ввод и вернуть меню.

Первый `/start` сохраняет ФИО из списка и текущие оценки как базу сравнения. Если студента нет в
какой-то ведомости или совпадение неоднозначно, бот перечисляет проблемные предметы. Отдельно
сообщает о незагруженном или устаревшем кэше. Доступ сохраняется: строка может появиться позже.
Повторный `/start` показывает меню и не сбрасывает ожидаемые изменения оценок.

При выключенных уведомлениях текущие оценки доступны; снимки продолжают обновляться.
Накопленные изменения не рассылаются после включения. Сообщения о новых таблицах и результатах
модерации остаются включены. Ручного ввода имени при первом входе нет.

## Таблицы и панель администратора

Кроме управления пользователями, администратор видит:

- **«Добавить таблицу»** (`/add`) — название, ссылка, выбор листов и настройка парсинга; сохраняет после подтверждения.
- **«Предложения»** (`/pending`) — настроить/отклонить предложения студентов.
- **«Обновить»** (`/refresh`) — обновить все одобренные таблицы и проверить изменения.
- **«Удалить таблицу»** (`/remove`) — выбор кнопкой из списка, затем подтверждение с названием.

Пример ссылки: `https://docs.google.com/spreadsheets/d/ID/edit#gid=42`.
Лист должен открываться на чтение по ссылке без входа в Google. Листы выбираются после отправки ссылки.
Приватные таблицы с OAuth и ссылки `/d/e/.../pubhtml` не поддерживаются.

После ссылки администратор выбирает листы и задаёт строки заголовков и столбцы ФИО
для каждого листа. Формат: `1-3 | B` (три уровня заголовков, ФИО в B).
Для обычной таблицы — `1 | A`, для раздельного ФИО — `2 | A:C`.
Команда `/layout 3 | 2` до отправки ссылки задаёт предварительные настройки;
для их применения на шаге настройки листа отправьте «по умолчанию».


| ФИО | Семинар 1 | Семинар 2 |
| --- | --- | --- |
| Иванов Иван Иванович | 5 | |
| Петров Петр Петрович | 4 | 5 |

Столбцы оценок выбираются текстом: `только C,E` или `исключить D:G`.
Многоуровневые заголовки преобразуются в пути; одинаковые пути различаются буквой столбца.
Перед сохранением бот показывает пути и пример значений. Подробности — в разделе «Сложные таблицы и несколько листов».
Максимальный размер CSV — 2 МБ; тайм-аут чтения — 30 секунд.

Названия проверяются без учёта регистра, лишних пробелов и е/ё. Дубликаты названий и ссылок
одобренных таблиц/предложений запрещены. При ошибке ссылки диалог остаётся на шаге ссылки.
Новая команда ввода заменяет текущий диалог; `/help`, `/tables`, `/grades` его не отменяют.
Незавершённые диалоги и подтверждения после перезапуска нужно начать заново.

При добавлении/одобрении таблицы уже вошедшие студенты получают название и ссылку.
Автор предложения получает результат модерации. При впервые найденной строке существующие
непустые оценки отправляются как новые. Идентификаторы таблиц не переиспользуются после удаления,
поэтому старые кнопки модерации не действуют на новые таблицы.

## Оценки, кэш и уведомления

Поиск ФИО не зависит от порядка слов, регистра, пробелов и е/ё. ФИ и полные ФИО сопоставляются
по набору слов. Совпадение всех слов имеет приоритет над сокращённым ФИО; опечатки проверяются,
только если нет совпадения без опечаток. Инициалы не сопоставляются. Если на лучшем уровне подходят две строки, оценки не выдаются;
нужно уточнить имя через администратора. Полных тёзок нельзя различить без дополнительного идентификатора.

`/grades` показывает последние три непустые оценки в обратном порядке столбцов. Среднее считается по всем
числовым значениям, количество — по всем непустым ячейкам, включая текстовые отметки. Ноль учитывается;
десятичные оценки принимаются с точкой или запятой. Запрос не изменяет очередь и снимки сравнения.

Заполнение пустой ячейки, новый непустой столбец, исправление и очистка оценки вызывают уведомление.
Все изменения по предметам за цикл собираются в одно сообщение. Очистка — «оценка удалена».
Для старых таблиц без явного выбора столбцов перестановка безопасна: сравнение по заголовкам.
Для настроенных через мастер таблиц после перестановки столбцов нужна повторная настройка. Переименование заголовка считается новым
семинаром; удаление целого столбца уведомления не вызывает. Перемещение столбцов ФИО требует
повторного добавления таблицы с новым расположением.

Кэш, время обновления, снимки и очередь хранятся в SQLite. Сбой Google сохраняет предыдущий кэш.
`/start`, `/grades` и `/tables` не обращаются к Google. Кэш старше двух интервалов помечается устаревшим.
Время показывается в МСК. Изменения между двумя опросами могут остаться незамеченными.
Обновления таблиц последовательные; при большом числе недоступных таблиц цикл может быть дольше интервала.

Длинные списки и уведомления имеют кнопки страниц. Страницы доступны только получателю,
административные — текущему администратору. Данные экранируются перед HTML-форматированием.
Страницы и завершённые записи очереди очищаются через 30 дней; страницы ожидающих сообщений сохраняются.

Снимки и уведомления записываются в одной транзакции. Доставка проверяется отдельно каждые 2 секунды.
Временные ошибки повторяются с возрастающей задержкой до часа; время следующей попытки сохраняется
при перезапуске. Неудачные первые сообщения не задерживают остальные. Ограничение Telegram
`retry_after` соблюдается целиком. Блокировка бота помечает ожидающие сообщения пользователя `blocked`;
некорректное сообщение — `failed`. Такие сообщения автоматически не пересылаются.
Падение между отправкой и фиксацией результата может вызвать повтор (доставка как минимум один раз).

## Миграция и эксплуатация

Перед обновлением сделайте резервную копию SQLite через SQLite backup API или остановите бота
и сохраните БД вместе с актуальными WAL-файлами. Новые таблицы/поля создаются при запуске.
Таблицы оценок, кэш и прежние регистрации сохраняются, но **старые самостоятельно введённые ФИО
не дают доступа**. Администратор должен заполнить новый список. Монитор не отправляет оценки
пользователям вне списка; ожидающие сообщения для них удаляются при попытке доставки.

Второй запуск на той же БД блокируется файловой блокировкой (Linux/macOS). Токен, API hash, БД и её служебные файлы не добавляются в Git.
Храните их в каталоге с доступом только для владельца. Общедоступные ссылки Google Sheets позволяют
читать сами ведомости вне бота: список доступа ограничивает бот, но не доступ к опубликованному листу.

## Проверка

```bash
pytest -q
ruff check gradebot tests
```

Тесты используют временные БД и имитацию Telegram/Google, без реальных токенов и сетевых запросов.
Проверяются запрет доступа, накопление контактов и сохранение всего списка, выбор пользователя Telegram,
смена/передача юзернейма, отзыв доступа, неизменяемое ФИО, устаревшие подтверждения, миграция,
права администратора, меню/FSM, CSV, кэш, изменение оценок, пагинация, повторная доставка и
ограничения Telegram

## SOCKS5-прокси

Установите обновлённые зависимости: `pip install -e '.[dev]'`. В `.env` добавьте:

```dotenv
PROXY_URL=socks5://127.0.0.1:1080
```

С авторизацией: `PROXY_URL=socks5://login:password@host:1080`.
Специальные символы в логине/пароле кодируются как в URL, например `@` — `%40`.
Поддерживается также `socks5h://`; имена серверов Telegram и Google разрешаются через прокси.
Настройка применяется к Telegram API и Google Sheets, включая проверку предложенных ссылок.
Пустой или отсутствующий `PROXY_URL` сохраняет прямое соединение. После изменения перезапустите бота.
Прокси должен быть доступен с компьютера, где запущен бот; порт `1080` здесь только пример.
Ошибочный формат настройки останавливает запуск с пояснением без вывода пароля.

## Логирование

`LOG_LEVEL=INFO` в `.env` включает журнал событий в stderr: запуск/остановку, обновления кэша,
результаты модерации, изменения доступа и сбои доставки. Записи содержат время в UTC,
категорию события, счётчики и внутренние номера таблиц/уведомлений. Уровень `DEBUG` дополнительно
показывает успешную доставку и отказ в доступе; доступны также `WARNING`, `ERROR`, `CRITICAL`.

ФИО, Telegram ID/username участников, оценки, названия и URL таблиц, токен бота, адрес/логин/пароль
прокси, тела сообщений и параметры запросов в журнал не записываются. Вместо текстов исключений
показываются категории ошибок (`timeout`, `network`, `telegram`, `database` и т. п.), без traceback
и локальных переменных. Сообщения сторонних библиотек преобразуются в `external_log` без исходного
текста; подробные HTTP-логи не включаются даже на `DEBUG`. Неожиданные ошибки запуска завершают
процесс с кратким сообщением вместо печати потенциально чувствительного исключения.

Кнопка «Все оценки: предмет» открывает оценки выбранного предмета по 10 на странице.
Поиск ФИО допускает одну опечатку в одном слове (добавление, пропуск, замену буквы или перестановку соседних букв). Точное совпадение имеет приоритет; неоднозначные совпадения не выбираются автоматически.

### Сложные таблицы и несколько листов

После `/add`, названия предмета и ссылки бот находит листы Google-таблицы.
Все листы выбраны по умолчанию. Кнопки позволяют переключать отдельные листы,
выбирать все или снимать выделение. Большой список разбивается на страницы.
При `/suggest` такой список сразу получает администратор; пользователь не выбирает настройки парсинга.
Администратор нажимает «Настроить выбранные листы» и последовательно настраивает каждый лист.

1. Бот автоматически определяет столбцы ФИО и строки заголовков и показывает короткую карточку:
   название листа, структуру, число выбранных столбцов и три примера путей со значениями
   из первой строки с распознанным ФИО. Само ФИО в карточке не показывается; пустые ячейки
   отмечаются как «пусто», длинные значения сокращаются. Если такой строки нет, бот сообщает об этом.
   «Далее» подтверждает лист. «Только итоги» оставляет столбцы с «итог» в пути;
   «Все оценки» возвращает все столбцы оценок. Столбец номера студента автоматически исключается.
   Для изменения структуры нажмите «Исправить структуру»: `1-3 | B` задаёт заголовки
   в строках 1–3 и ФИО в B; `2 | A:C` — раздельные фамилию, имя и отчество.
   Если автоопределение не удалось, бот сразу предлагает компактный ручной ввод.
2. Полный список путей доступен по кнопке «Список столбцов», с отметками выбранных столбцов. Верхние уровни заголовков
   заполняются вправо в пределах родительской группы: например,
   `03.09.2026 → Семинар → Выход к доске`. Нижний уровень не заполняется вправо.
   CSV не содержит геометрию объединений: проверьте полученные пути по предпросмотру.
   Совпадающие пути получают суффикс с буквой столбца.
3. Настройка оценок выполняется **текстом**, без кнопки на каждый столбец:
   - `только C,E` — оставить только эти столбцы, например два ИТОГ;
   - `исключить C:F,J` — убрать диапазон и отдельный столбец;
   - `только по названию итог` — оставить столбцы с «итог» в любом уровне пути;
   - `исключить по названию итог,округление` — исключить по частям названий (без учёта регистра);
   - `все` — восстановить все столбцы оценок;
   - `назад` — изменить строки заголовков и ФИО;
   - `готово` — подтвердить лист и перейти к следующему;
   - `пропустить` — исключить текущий лист.
4. После настройки всех листов бот показывает сводку. Кнопка «Сохранить» добавляет
   все настроенные листы вместе. При конфликте названия или ссылки ничего не добавляется.

Для таблицы с квизами нажмите «Только итоги». Для таблицы с датами проверьте
автоматически найденную структуру и нажмите «Далее» или исключите ненужные столбцы текстом.
Столбцы также можно задавать номерами: `только 3,5-7`.

Каждый лист хранится отдельно, с названием `Предмет · Лист` (для одного листа — просто `Предмет`).
Диапазон заголовков и выбранные столбцы сохраняются в SQLite и используются при обновлении
и чтении кэша. При перестановке столбцов настройку нужно выполнить заново, поскольку выбор
задаётся физическими столбцами. `/cancel` отменяет незавершённую настройку без добавления листов.
Настройка в процессе `/add` хранится в памяти и после перезапуска начинается заново;
выбор листов в предложении пользователя сохраняется в SQLite.


### Оповещения об изменении таблиц

При каждом плановом обновлении и `/refresh` бот проверяет списки листов сохранённых
Google-таблиц и структуру заголовков сохранённых листов. Администратор получает отдельное
уведомление, если появился новый лист, лист переименован, удалён или скрыт, изменились
заголовки, их порядок, число столбцов или расположение ФИО/заголовков.
Проверяются и исключённые из парсинга столбцы в пределах заголовков сохранённого листа.
Изменения оценок и добавление строк студентов сами по себе не считаются изменением структуры.
Изменения оформления, цветов, ширины столбцов и формул без изменения отображаемых значений
не отслеживаются: источник данных — CSV.

Уведомления приходят только текущему администратору, независимо от переключателя уведомлений
об оценках. Состояние проверки хранится в SQLite вместе с очередью доставки: одно и то же
изменение не рассылается повторно после обновления или перезапуска. Ошибка загрузки списка
листов не считается удалением листов и не мешает обновлять оценки.

Новые листы не добавляются автоматически: сообщение содержит ссылку, нужные листы добавляются
через `/add`. Если структура ломает парсинг, бот сохраняет предыдущий кэш и предупреждает,
что настройки нужно проверить. Для повторной настройки лист удаляется через `/remove`
и добавляется заново через `/add`.

Для вновь добавленных через мастер таблиц исходный список листов запоминается при сохранении.
Для таблиц, сохранённых до появления этой функции, первое успешное обновление запоминает
список листов без рассылки; дальнейшие изменения отслеживаются. Заголовки при первом обновлении
сравниваются с уже имеющимся кэшем.
