# Бот оценок учебной группы

Python 3.11+, aiogram 3, SQLite. Один запущенный экземпляр — одна группа и один администратор.
Бот читает Google Sheets, периодически сравнивает оценки и отправляет студентам личные сообщения.
CI не используется.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
export BOT_TOKEN='токен от @BotFather'
export DATABASE_PATH='grades.sqlite3'
export POLL_INTERVAL=60
export CONTACT_USERNAME='your_telegram_username'

gradebot admin 123456789
gradebot run
```

Настройки можно сохранить в `.env` в каталоге запуска (пример — `.env.example`):

```dotenv
BOT_TOKEN=токен_бота
DATABASE_PATH=grades.sqlite3
POLL_INTERVAL=60
CONTACT_USERNAME=your_telegram_username
```

`.env` загружается автоматически. Переменные окружения имеют приоритет над `.env`, а `--interval`
переопределяет `POLL_INTERVAL`. Интервал задаётся в секундах и отображается в `/help` в секундах,
минутах или часах. `CONTACT_USERNAME` — контакт в Telegram, можно с `@` или без него;
если контакт не указан, строка «Для связи» не показывается. После смены настроек перезапустите бота.
Справка начинается с «Рад тебя видеть, ФИО» по сохранённому имени (до регистрации — без ФИО).
Затем идут разделы «Описание» и «Управление», для администратора — также «Админ».
В конце курсивом показывается время самого последнего успешного обновления кэша среди одобренных
таблиц в МСК. Кэш предложений на модерации не учитывается; если кэша ещё нет, отображается соответствующая подпись.
`gradebot --db /path/group.sqlite3 admin 123456789` позволяет выбрать БД явно.
Смена администратора — повторный вызов `gradebot admin НОВЫЙ_ID`. ID и права сохраняются в SQLite;
новый админ должен сам начать диалог с ботом и зарегистрировать ФИО, как остальные студенты.
Нельзя назначить админа командой Telegram. Токен и БД не попадают в Git.

## Таблицы и команды

Поддерживаются обычные ссылки `https://docs.google.com/spreadsheets/d/ID/edit#gid=0`.
У листа должен быть доступ на чтение по ссылке без авторизации. `gid` выбирает вкладку;
каждую вкладку добавляют отдельно. Приватные таблицы с Google OAuth, таблицы внутри Google Docs
и ссылки опубликованного вида `/d/e/.../pubhtml` в этом каркасе не поддерживаются.

Все команды ввода работают пошагово. Отправьте команду, затем отвечайте на вопросы бота.
`/cancel` отменяет текущий диалог, новая команда ввода начинает новый. `/help`, `/tables` и `/grades`
не отменяют незавершённый ввод. Состояния независимы для каждого пользователя; после перезапуска
незавершённый диалог нужно начать заново, сохранённые ФИО и таблицы остаются в SQLite.

Обычные пользователи видят в `/help` только свои команды:

- `/start` — ввод ФИО и проверка всех одобренных таблиц.
- `/name` — ввод нового ФИО и подтверждение сохранения.
- `/grades` — оценки из последнего сохранённого кэша всех таблиц.
- `/tables` — предметы и ссылки.
- `/suggest` — предложение таблицы: сначала название, затем ссылка.
- `/cancel` — отмена текущего ввода.
- `/help` — краткая справка.

У администратора дополнительно:

- `/add` — название предмета, затем ссылка; добавление без модерации.
- `/refresh` — принудительное обновление кэша с уведомлениями при изменениях.
- `/pending` — сохранённые предложения с кнопками принятия/отклонения.
- `/remove` — запрос номера таблицы, которую нужно удалить (номер из `/tables`).

Пример добавления:

```text
/add
Бот: Отправь название предмета
Математический анализ
Бот: Отправь ссылку на таблицу
https://docs.google.com/spreadsheets/d/ID/edit#gid=42
Бот: Таблицу добавил
```

Названия одобренных таблиц и предложений проверяются сразу после ввода: при совпадении бот
просит другое название, не переходя к ссылке. Проверка не зависит от регистра, лишних пробелов
и различия `е/ё`. Если название заняли во время ввода ссылки, бот возвращается к вводу названия.
Повторная проверка при сохранении предотвращает дубликаты от одновременных диалогов.

При ошибке чтения или повторном добавлении ссылки бот остаётся на шаге ссылки: можно попробовать другую
ссылку без повторного ввода названия. `/suggest` использует такой же диалог и отправляет таблицу на
модерацию. Даже администратор через `/suggest` создаёт предложение; для прямого добавления — `/add`.

По умолчанию заголовки в первой строке, ФИО в первом столбце. Если расположение другое, перед
отправкой ссылки можно указать `/layout 3 | 2`: заголовки в третьей строке, ФИО в столбце B.
Для ФИО в отдельных столбцах: `/layout 1 | 1,2,3`. Это необязательная настройка внутри диалога
добавления или предложения таблицы.
Все остальные столбцы с непустыми заголовками считаются оценками — служебные колонки тоже будут отслеживаться.
Заголовки семинаров должны быть уникальными и стабильными, например `Семинар 1 (07.10)`.
Пустые заголовки игнорируются. Объединённые ячейки и многоуровневые заголовки нужно привести к одной строке.

| ФИО | Семинар 1 | Семинар 2 |
| --- | --- | --- |
| Иванов Иван Иванович | 5 | |
| Петров Петр | 4 | 5 |

## Поведение

После `/start` бот кратко рассказывает о себе и запрашивает ФИО. После ввода приветствует
«Добро пожаловать, ФИО», указывает `/help` и перечисляет только таблицы,
в которых пользователя не удалось найти. При успешном поиске во всех таблицах дополнительного сообщения нет. Отдельно перечисляет отсутствующие/неоднозначные совпадения
и таблицы, для которых ещё нет кэша. Текущие значения сохраняются как база сравнения.
`/name` запрашивает новое ФИО и отвечает «Сохранил»; после смены имени монитор начнёт новую проверку.
`/grades` мгновенно читает сохранённый кэш и показывает по каждому предмету последние пять
непустых оценок в порядке столбцов слева направо, каждую с маркером `-`. Среднее считается по всем числовым значениям,
а количество — по всем непустым ячейкам, включая текстовые отметки. Пустые ячейки пропускаются,
ноль учитывается; десятичные оценки могут использовать точку или запятую. Среднее округляется
до двух знаков, при отсутствии числовых значений показывается «—». Запрос не меняет снимки и очередь,
поэтому изменения по-прежнему вызовут уведомления при очередном опросе.
После добавления или одобрения новой таблицы все зарегистрированные пользователи получают сообщение
с названием предмета и ссылкой на саму таблицу. Автор предложения получает отдельное сообщение об
одобрении или отклонении. При впервые найденной строке существующие непустые оценки отправляются как новые.
Регистрация разрешена и когда ФИО не найдено: строка может появиться позже.

Поиск не зависит от порядка слов, регистра, пробелов и различия `е/ё`. Полные ФИО и ФИ сопоставляются
по набору слов. Инициалы и опечатки автоматически не исправляются. Если подходят две строки,
оценки не отправляются: при регистрации пользователь получает сообщение о неоднозначности и может уточнить ФИО.
После регистрации отсутствующая/неоднозначная строка пропускается с сохранением последнего снимка.
Нельзя уверенно различить полных тёзок без дополнительного идентификатора.

Новый непустой столбец, заполнение пустой ячейки, исправление и очистка оценки вызывают уведомление:

```text
Найдены новые оценки:

ОРГ
- Семинар 6: 4
- Семинар 7: 2

История
- Контрольная: 2
```

Все изменения оценок по предметам за цикл собираются в одно сообщение каждому пользователю.
Предметы выделены жирным, оценки перечислены с маркером `-` и названием столбца.
Исправления показывают новое значение, очистка ячейки — «оценка удалена».
Пустой новый столбец не вызывает сообщений.
Перестановка столбцов оценок безопасна: сравнение ведётся по заголовкам. Переименование заголовка
считается новым семинаром, удаление целого столбца — изменением структуры без уведомления.
Перемещение столбцов ФИО требует удаления и повторного добавления таблицы с новой настройкой.

Изменения обнаруживаются опросом (по умолчанию раз в 60 секунд), а не push-событиями Google.
Изменения между двумя опросами могут остаться незамеченными. Не запускайте два процесса с одной БД.
Бот использует только личные сообщения; все зарегистрированные пользователи получают собственные оценки
из всех одобренных таблиц группы.

Снимки и уведомления создаются в одной транзакции SQLite. При временной ошибке Telegram сообщение
остаётся в очереди и повторяется после перезапуска. Если процесс упал после отправки, но до фиксации
доставки, возможно повторное сообщение (доставка как минимум один раз). Блокировка бота пользователем
помечает сообщение `blocked`; старые сообщения автоматически не пересылаются после разблокировки.
Ошибки Google логируются и не стирают предыдущий снимок. Если админ ещё не запустил бота,
предложение всё равно сохраняется и видно в `/pending`.

## Кэш и сообщения

Полные данные каждого листа и время успешной загрузки сохраняются в SQLite. Фоновая проверка
обновляет кэш; `/grades`, `/start` и `/tables` не обращаются к Google и не ждут окончания сетевых
запросов. Добавление и одобрение таблицы сразу сохраняют первый кэш. Если обновление не удалось,
предыдущие данные остаются доступными. После миграции существующие таблицы заполняются первым
фоновым опросом; до него бот сообщает, что кэш ещё не загружен.

Под оценками и в списке таблиц показывается время последнего успешного обновления в МСК.
Кэш считается устаревшим, когда его возраст превышает два интервала опроса (по умолчанию 120 секунд).
В этом случае появляется пометка «Кэш устарел». Проверка ФИО при регистрации тоже использует кэш
и указывает устаревшие данные. Кэш и снимки для уведомлений переживают перезапуск.

Списки оценок, таблиц и предложений отправляются одним сообщением. Если список не помещается,
под сообщением появляются кнопки страниц; переключение редактирует то же сообщение.
Длинное уведомление об оценках также приходит один раз с кнопками страниц. Страницы сохраняются
в SQLite и доступны после перезапуска только получателю; административные списки — текущему админу.
Заголовки выделены жирным, даты кэша — курсивом. Данные таблиц экранируются перед HTML-форматированием.

Бот показывает ссылки `/edit#gid=...`, а экспорт CSV использует только для чтения.
Существующие сохранённые экспортные ссылки автоматически преобразуются при запуске.
Миграция создаёт новые таблицы кэша/страниц и поля очереди без удаления пользователей и оценок.
Уведомления о таблицах и результатах модерации сохраняются в той же очереди с повторной доставкой;
смена ФИО очищает только недоставленные уведомления об оценках.

## Проверка

```bash
pytest -q
ruff check gradebot tests
```

Тесты работают без токена и доступа к реальным таблицам: парсинг CSV, перестановки ФИО,
неоднозначность, конфигурация листа, новые/исправленные/удалённые оценки, восстановление очереди,
сбои чтения, ограничения команд администратора, пошаговые FSM-диалоги, повторный ввод после
ошибок, отмена, разделение состояний пользователей, кэш после перезапуска, устаревание кэша,
миграция старой БД, объединение уведомлений, пагинация и результаты модерации. Для проверки реальной интеграции нужны
токен Telegram и доступная Google Sheets таблица.

`/refresh` доступна только админу и обновляет все одобренные таблицы тем же способом,
что фоновая проверка. Повторных уведомлений о неизменившихся оценках нет. После завершения
команды новый интервал отсчитывается заново, в том числе при частичном сбое Google.
Параллельные ручные и фоновые проверки выполняются последовательно; фоновая проверка,
ожидавшая завершения ручной, учитывает перенесённый срок. Ошибки отдельных таблиц перечисляются
в ответе, их старый кэш сохраняется.

Перед длительными сетевыми операциями (`/refresh`, проверкой ссылки при добавлении и одобрением
таблицы) бот отправляет «Секундочку», затем результат или сообщение об ошибке.
Команды чтения кэша отвечают сразу без промежуточного сообщения.
