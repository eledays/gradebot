# Бот оценок учебной группы

Python 3.11+, Linux/macOS, aiogram 3, SQLite. Один бот — одна группа и один администратор.
Бот читает общедоступные Google Sheets, показывает оценки и присылает личные уведомления.

## Быстрый запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,usernames]'
cp .env.example .env
# Заполните BOT_TOKEN, CONTACT_USERNAME и при необходимости TELEGRAM_API_ID/TELEGRAM_API_HASH.
gradebot admin 123456789
gradebot run
```

`BOT_TOKEN` выдаёт @BotFather. `CONTACT_USERNAME` — контакт администратора для сообщений об отказе
в доступе. `DATABASE_PATH` по умолчанию `grades.sqlite3`; `POLL_INTERVAL` — интервал в секундах,
по умолчанию 60, минимум 10. Переменные окружения имеют приоритет над `.env` в каталоге запуска;
`--interval` переопределяет `POLL_INTERVAL`. После изменения настроек перезапустите бота.

Администратор назначается только локально командой `gradebot admin TELEGRAM_ID`.
Для другой БД: `gradebot --db /path/group.sqlite3 admin TELEGRAM_ID`.
Повторный вызов меняет администратора. Новый администратор открывает `/start` и сразу получает
панель управления; ФИО для управления не требуется. Чтобы получать свои оценки, он добавляет себя
в список пользователей тем же способом, что студентов.

## Как администратору открыть доступ

1. Откройте бота и нажмите «Старт».
2. Нажмите **«Добавить пользователей»** (`/access`).
3. Выберите человека кнопкой **«Выбрать пользователя»**, затем отправьте его ФИО как в ведомости.
   Telegram сразу передаёт ID выбранного аккаунта; предварительный вход студента не требуется.
4. Проверьте имя и ID в предложенном списке и нажмите **«Сохранить»**.
5. Добавьте таблицы оценок кнопкой **«Добавить таблицу»**.
6. Отправьте студентам ссылку на бота. Каждый нажимает «Старт» и сразу видит меню — ФИО вводить не нужно.

Вместо выбора одного человека можно отправить до 50 строк за раз:

```text
@ivanov | Иванов Иван Иванович
@petrov | Петров Петр Петрович
```

Бот **сразу обращается к Telegram и преобразует каждый юзернейм в ID**, до сохранения списка
и до первого входа студента. Если хотя бы один аккаунт не найден, оказался ботом/каналом или
Telegram недоступен, весь список остаётся несохранённым. Можно исправить строки и отправить снова.
Два юзернейма одного аккаунта в одном списке отклоняются. Сохранение добавляет/обновляет указанные
аккаунты, остальные строки списка сохраняются.

### Настройка поиска по юзернейму

Обычный Telegram Bot API не ищет людей по произвольному юзернейму. Для этого используется
официальный MTProto-метод [`contacts.resolveUsername`](https://core.telegram.org/method/contacts.resolveUsername),
доступный ботам, через Telethon. Нужны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` приложения,
созданного на [my.telegram.org](https://my.telegram.org/apps):

```dotenv
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=your_api_hash
```

Установите дополнение `pip install -e '.[usernames]'` и перезапустите бота.
Подключается **сам бот по BOT_TOKEN**: вход в личный Telegram-аккаунт, номер телефона и код
подтверждения не нужны. MTProto-сессия хранится только в памяти, файл сессии не создаётся.
Поиск всегда выполняется заново в Telegram, чтобы старый кэш юзернеймов не привязал другой аккаунт.
Без этих настроек остаётся доступен выбор человека кнопкой Telegram; ввод списка юзернеймов
показывает понятную инструкцию и никому не открывает доступ.

### Управление списком

**«Пользователи»** (`/members`) показывает ФИО, юзернейм на момент добавления, сохранённый ID
и статус первого входа. Юзернейм служит подписью; после сохранения доступ определяется **только ID**.
Смена/удаление юзернейма не лишает студента доступа. Новый владелец прежнего юзернейма доступа не получает.
Пользователь без юзернейма добавляется через кнопку Telegram.

Для исправления ФИО снова выберите того же человека или введите его **текущий** юзернейм с новым ФИО.
Предпросмотр показывает прежнее и новое имя. При смене ФИО очищаются снимки сравнения и ожидающие
уведомления об оценках; другие ожидающие сообщения сохраняются. Студент не может менять ФИО командой
`/name`: бот направляет его к администратору.

**«Закрыть доступ»** (`/revoke`) показывает список с кнопками выбора, затем ФИО и подтверждение.
Также можно отправить ID из списка.
Удаляются разрешение, регистрация, снимки, личные страницы и очередь сообщений этого пользователя.
Он больше не может получать данные или переключать старые страницы. Уже отправленные сообщения
в Telegram команда не удаляет. Доступ текущему администратору так закрыть нельзя.

Все команды и кнопки доступны только разрешённым ID и текущему администратору. Посторонним бот
отказывает в доступе и показывает контакт администратора, если он задан. Юзернейм входящего сообщения
не используется для автоматической выдачи прав. В групповых чатах оценки не показываются.

## Меню студента

- **«Мои оценки»** (`/grades`) — оценки из сохранённого кэша, без ожидания Google.
- **«Таблицы»** (`/tables`) — предметы, ссылки, время обновления.
- **«Уведомления»** (`/notifications`) — выключить или включить уведомления об изменениях оценок.
- **«Помощь»** (`/help`) — справка и контакт администратора.
- **«Предложить таблицу»** (`/suggest`) — название, затем ссылка; предложение проверяет администратор.
- `/cancel` — отменить текущий ввод и вернуть меню.

Первый `/start` сохраняет ФИО из списка и текущие оценки как базу сравнения. Если студента нет в
какой-то ведомости или совпадение неоднозначно, бот перечисляет проблемные предметы. Отдельно
сообщает о незагруженном или устаревшем кэше. Доступ сохраняется: строка может появиться позже.
Повторный `/start` показывает меню и не сбрасывает ожидаемые изменения оценок.

При выключенных уведомлениях текущие оценки доступны; снимки продолжают обновляться.
Накопленные изменения не рассылаются после включения. Сообщения о новых таблицах и результатах
модерации остаются включены. Ручного ввода имени при первом входе нет.

## Таблицы и панель администратора

Кроме управления пользователями, администратор видит:

- **«Добавить таблицу»** (`/add`) — название, затем ссылка; сразу одобряет таблицу.
- **«Предложения»** (`/pending`) — принять/отклонить предложения студентов.
- **«Обновить»** (`/refresh`) — обновить все одобренные таблицы и проверить изменения.
- **«Удалить таблицу»** (`/remove`) — выбор кнопкой из списка, затем подтверждение с названием.

Пример ссылки: `https://docs.google.com/spreadsheets/d/ID/edit#gid=42`.
Лист должен открываться на чтение по ссылке без входа в Google. Каждую вкладку добавляйте отдельно.
Приватные таблицы с OAuth и ссылки `/d/e/.../pubhtml` не поддерживаются.

По умолчанию заголовки в строке 1, ФИО в столбце A. Бот объясняет это перед вводом ссылки.
Для другого расположения внутри диалога: `/layout 3 | 2` (заголовки в третьей строке, ФИО в B),
либо `/layout 1 | 1,2,3` (ФИО в отдельных столбцах A/B/C).

| ФИО | Семинар 1 | Семинар 2 |
| --- | --- | --- |
| Иванов Иван Иванович | 5 | |
| Петров Петр Петрович | 4 | 5 |

Все остальные столбцы с непустыми заголовками отслеживаются, включая служебные.
Заголовки должны быть уникальными и стабильными. Пустые заголовки игнорируются.
Объединённые ячейки и многоуровневые заголовки нужно привести к одной строке.
Максимальный размер CSV — 2 МБ; тайм-аут чтения — 30 секунд.

Названия проверяются без учёта регистра, лишних пробелов и е/ё. Дубликаты названий и ссылок
одобренных таблиц/предложений запрещены. При ошибке ссылки диалог остаётся на шаге ссылки.
Новая команда ввода заменяет текущий диалог; `/help`, `/tables`, `/grades` его не отменяют.
Незавершённые диалоги и подтверждения после перезапуска нужно начать заново.

При добавлении/одобрении таблицы уже вошедшие студенты получают название и ссылку.
Автор предложения получает результат модерации. При впервые найденной строке существующие
непустые оценки отправляются как новые. Идентификаторы таблиц не переиспользуются после удаления,
поэтому старые кнопки модерации не действуют на новые таблицы.

## Оценки, кэш и уведомления

Поиск ФИО не зависит от порядка слов, регистра, пробелов и е/ё. ФИ и полные ФИО сопоставляются
по набору слов. Инициалы и опечатки не исправляются. Если подходят две строки, оценки не выдаются;
нужно уточнить имя через администратора. Полных тёзок нельзя различить без дополнительного идентификатора.

`/grades` показывает последние пять непустых оценок в порядке столбцов. Среднее считается по всем
числовым значениям, количество — по всем непустым ячейкам, включая текстовые отметки. Ноль учитывается;
десятичные оценки принимаются с точкой или запятой. Запрос не изменяет очередь и снимки сравнения.

Заполнение пустой ячейки, новый непустой столбец, исправление и очистка оценки вызывают уведомление.
Все изменения по предметам за цикл собираются в одно сообщение. Очистка — «оценка удалена».
Перестановка столбцов безопасна: сравнение по заголовкам. Переименование заголовка считается новым
семинаром; удаление целого столбца уведомления не вызывает. Перемещение столбцов ФИО требует
повторного добавления таблицы с новым расположением.

Кэш, время обновления, снимки и очередь хранятся в SQLite. Сбой Google сохраняет предыдущий кэш.
`/start`, `/grades` и `/tables` не обращаются к Google. Кэш старше двух интервалов помечается устаревшим.
Время показывается в МСК. Изменения между двумя опросами могут остаться незамеченными.
Обновления таблиц последовательные; при большом числе недоступных таблиц цикл может быть дольше интервала.

Длинные списки и уведомления имеют кнопки страниц. Страницы доступны только получателю,
административные — текущему администратору. Данные экранируются перед HTML-форматированием.
Страницы и завершённые записи очереди очищаются через 30 дней; страницы ожидающих сообщений сохраняются.

Снимки и уведомления записываются в одной транзакции. Доставка проверяется отдельно каждые 2 секунды.
Временные ошибки повторяются с возрастающей задержкой до часа; время следующей попытки сохраняется
при перезапуске. Неудачные первые сообщения не задерживают остальные. Ограничение Telegram
`retry_after` соблюдается целиком. Блокировка бота помечает ожидающие сообщения пользователя `blocked`;
некорректное сообщение — `failed`. Такие сообщения автоматически не пересылаются.
Падение между отправкой и фиксацией результата может вызвать повтор (доставка как минимум один раз).

## Миграция и эксплуатация

Перед обновлением сделайте резервную копию SQLite через SQLite backup API или остановите бота
и сохраните БД вместе с актуальными WAL-файлами. Новые таблицы/поля создаются при запуске.
Таблицы оценок, кэш и прежние регистрации сохраняются, но **старые самостоятельно введённые ФИО
не дают доступа**. Администратор должен заполнить новый список. Монитор не отправляет оценки
пользователям вне списка; ожидающие сообщения для них удаляются при попытке доставки.

Второй запуск на той же БД блокируется файловой блокировкой (Linux/macOS). Токен, API hash, БД и её служебные файлы не добавляются в Git.
Храните их в каталоге с доступом только для владельца. Общедоступные ссылки Google Sheets позволяют
читать сами ведомости вне бота: список доступа ограничивает бот, но не доступ к опубликованному листу.

## Проверка

```bash
pytest -q
ruff check gradebot tests
```

Тесты используют временные БД и имитацию Telegram/Google, без реальных токенов и сетевых запросов.
Проверяются запрет доступа, преобразование списка в ID до входа, выбор пользователя Telegram,
смена/передача юзернейма, отзыв доступа, неизменяемое ФИО, устаревшие подтверждения, миграция,
права администратора, меню/FSM, CSV, кэш, изменение оценок, пагинация, повторная доставка и
ограничения Telegram. Для тестов адаптера MTProto установите дополнение `usernames`.
